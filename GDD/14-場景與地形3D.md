## 0. 本檔存在的理由與對舊規格的修正

《00 總覽》與《06 美術規格》寫的是 **HTML5 2D 時代的「水彩手繪風、程式化向量繪製」**。
2026-07-26 使用者裁定：**戰場改為全 3D，且要能像現實一樣進建築、跑壕溝、躲草叢**。
故本檔就「戰場場景」一項**取代** GDD/06 的向量繪製規範（UI/立繪不受影響，仍走原規格）。

### 0a. 畫質路線（2026-07-26 使用者選定）

**低多邊形 ＋ 大幅提升打光與後製**。理由：現有角色（Quaternius hr_ 骨架）與程式生成載具都是
低多邊形，換寫實 PBR 會格格不入且要全部重做；質感的來源改成「光、影、霧、色調、材質分層」。

- 渲染管線：Godot **Forward+**（原本是 gl_compatibility，做不了 SSAO/SSIL/體積霧）。
- 必備：真實比例的太陽角度與色溫、軟陰影、SSAO、色調映射(ACES)、輕度泛光、
  高度霧/體積霧、地表材質依高度與坡度分層（草／土／碎石／泥）。
- **禁止**：為了「像照片」而改用寫實貼圖包（與角色風格衝突，且效能與體積失控）。

## 1. 地形（可跑、可躲、有高低差）

| 地形 | 幾何 | 戰術效果 |
|------|------|----------|
| 壕溝 | 深 1.4m、寬 2.2m 的下挖通道，含土堤 | 站在溝內＝**半身掩體**（被命中 ×0.5）且對溝外視線受限；沿溝移動不被高地觀測 |
| 彈坑 | 半徑 2~4m 的凹陷 | 同壕溝但只保護單點；移動 AP ×2（GDD/01 §5） |
| 土堤／矮牆 | 高 0.9m 的長條隆起 | 方向性掩體（沿用既有 cover 判定） |
| 草叢 | 高 0.8~1.2m 的草地區塊 | **蹲伏且未開火時隱蔽**（GDD/01 §5a），站立或開火後失效 |
| 高地 | 平滑起伏，最高 6m | 高處對低處視線加成；上坡移動 AP 成本 ×1.5 |

- 地形以**高度圖 + 資料驅動**產生：`data/maps.json` 既有的 `foxholes` 等欄位沿用，
  新增 `trenches`（折線＋寬度）、`hills`（中心＋半徑＋高度）、`grass`（矩形區塊）。
- 單位一律**貼合地形高度**（含既有的蹲/趴/貼地邏輯），不可再假設地面 y=0。

## 2. 可進入的建築（程式生成模組化）

- 以「牆 / 地板 / 門 / 窗 / 樓梯」模組程式組成，**保證每棟都有真正的室內空間**。
- 每棟建築產生一份結構資料：外牆線段、門位置、窗位置、樓層高度、可站立區域。
  掩體與視線系統直接吃這份資料，不再靠 AABB 猜。
- **牆擋視線與子彈**；**窗**可射擊但提供 ×0.5 掩體；**門**是唯一的進出點。
- 鏡頭處理：單位在室內時，攝影機與單位之間的屋頂／牆自動淡出（不是整棟消失）。
- 多樓層：樓梯連通；上層單位對外視野加成，對地面單位有俯射優勢。

### 2a. 實體規則（畫出來的東西就要擋得住人）

戰場上「看得到的東西」與「擋得住人的東西」必須是同一份真相，否則第三人稱一走過去就穿模，
所有掩體與路線規劃都變成假的。**擋人的清單（每幀對所有單位生效，敵我與任何設座標的路徑都不例外）**：

| 物件 | 形狀 | 半徑 | 說明 |
|------|------|------|------|
| 建築牆 | 線段 | 0（牆厚另計） | 門窗缺口天生可通行，門是唯一入口 |
| 紐澤西護欄 | 線段 | 0.36m | 整排一條線段，中間不留縫 |
| 木柵欄 | 線段 | 0.14m | 逐段橫杆；只登記柱子的話人會從兩柱之間穿過去 |
| 龍牙拒馬 | 圓 | 0.62m | 各自獨立＝車過不去、人可以繞（設計本意） |
| 電線桿 | 圓 | 0.32m | |
| 樹幹 | 圓 | 0.40m（單株）／0.85m（樹叢） | 走得過樹葉、走不過樹幹 |
| 載具 | 圓 | 1.60m | 坦克 3.1m 寬，人不可能穿過去；載具本身半徑同值 |

**不擋人**：路面、瓦礫碎石（跨得過去）、草叢（只給隱蔽）、沙包（掩體點，AI 要走到旁邊）。

## 3. 與既有系統的接點（不可打破）

1. **掩體**：壕溝/土堤/窗沿用 `cover_at()` 的方向性判定，只是掩體來源多了地形與建築。
2. **視線**：`_los_clear()` 除了建築圓形，改吃「牆線段」與「地形高度」。
3. **迷霧**：室內單位在門窗視線外不可見；草叢隱蔽沿用 GDD/01 §5a。
4. **移動**：AP 成本依地形（上坡 ×1.5、彈坑/水 ×2）；門是唯一進出點，不可穿牆。
5. **姿勢**：既有蹲/趴/蹲行不變，但要在斜面與溝內正確貼地。

## 4. 效能預算（dept-10）

- 目標：**16 單位同場 ≥ 60 FPS**（幀時 < 16ms），與現有 `[perf]` 量測同一把尺。
- 草叢用 MultiMesh，建築用共用材質，地形單一網格；陰影距離維持 80m。
- 每加一項新場景元素都要重跑 `[perf]`，退步超過 50% 就要先優化再往下做。

## 5. 驗收標準（dept-15）

每一項都要有**實拍**與**數據**，不接受「看起來差不多」：
- `[terrainchk]`：單位在壕溝內的高度低於地面、溝內取得掩體、上坡 AP 成本提高。
- `[buildingchk]`：單位能從門進入、進入後屋頂淡出、牆確實擋視線與子彈、窗可射擊。
- `[grasschk]`：蹲伏在草叢中不被敵方警戒觸發，站起或開火後恢復可見。
- `[solidchk]`：**一律「用走的」驗，不准把單位直接放到定點**（那等於繞過碰撞）。
  對牆走進不去、對門走進得去、對護欄走停在前方、對坦克走停在車體外。
- `[perf]`：16 單位幀時。
