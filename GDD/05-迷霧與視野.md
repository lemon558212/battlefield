# 05. 戰爭迷霧與視野（v2）
<!-- v2.0 | 2026-07-07 | 視野權威。引擎：js/fog.js + game.js render -->

## 1. 三態迷霧（每格一個狀態）

戰場切成 `FOG_CELL=32px` 的網格（960×600 → 30×19 格）。每格對我方有三態：

| 態 | 定義 | 渲染 | 敵單位 |
|----|------|------|--------|
| unseen（未探索） | 從開局到現在，我方視野從未覆蓋 | 全黑遮罩（alpha 0.85） | 完全不畫 |
| explored（已探索無視野） | 曾被視野覆蓋，但當前無我方單位看得到 | 暗遮罩（alpha 0.45），地形可見 | 不畫（記憶不含移動敵人） |
| visible（當前可見） | 當前有我方存活單位視野覆蓋 | 無遮罩 | 依 canSee 規則畫 |

## 2. 視野半徑（sightRadius，px）

| 兵種類 | 半徑 | 備註 |
|--------|------|------|
| rifleman（偵察） | 170 | 全軍最廣（GDD/02 視野 1.3×） |
| specops / sniper | 150 | |
| 一般 land | 120 | |
| sam | 110 | 對空探測遠：對 air 視野 300 |
| destroyer | 200 | 海上瞭望 |
| 其他 sea | 150 | |
| air（fighter/attacker/gunship） | 240 | 空中視野最廣 |

- 以色列 `intel_superiority` 特性：全軍 sightRadius ×1.2。
- 烏克蘭 `drone_recon`：前 3 回合視野無視草叢隱蔽（已在 combat.canSee 實作）。

## 3. 視野計算（每次我方單位移動/回合開始時重算）

```
visibleCells = ∅
for 每個我方存活單位 u:
  for 半徑內每格 c:
    若 u 到 c 的直線不被 solid 阻擋（air 單位無視阻擋）:
      visibleCells.add(c); exploredCells.add(c)
```

- 效能：視野只在（a）我方單位移動每 0.1s（b）回合切換 時重算，不每幀算。
- 快取於 `Fog.visible`(Set) / `Fog.explored`(Set)，render 直接查。

## 4. 與敵單位顯示的關係（整合既有 canSee）

敵單位可見 = 其所在格 ∈ visible **且** 通過 `Combat.canSee`（草叢/潛艦隱蔽）。二者皆真才畫。潛艦/草叢特種兵即使在 visible 格仍隱蔽。

### 部署保密（2026-07-11）

- 我方部署階段只渲染我方單位、我方部署框與公開地形；敵方 AI／連線玩家的部署單位完全不建立可見外觀、不畫血條，也不可被點擊。
- 按下「開始戰鬥」後才依正常迷霧與視線規則顯示敵軍；不得因 `state==="deploy"` 繞過迷霧。
- 單機 AI 可在記憶體中先完成部署，但其座標在開戰前屬於隱藏資訊。

## 5. 迷霧對 AI 的公平性

AI（敵方）也只用「敵方視角視野」決策：`AI.planUnit` 選目標時，只考慮「敵方視野可見的我方單位」；我方單位躲在敵視野外則 AI 看不到、不鎖定（改為向我主堡推進）。函式 `Fog.sideCanSee(side, target)`。

### 5a. Godot 版落地（2026-08-22 補回）

**這一節在 Godot 版曾整段遺失**：移植時 `_ai_plan` 直接掃 `units` 取所有活著的敵方單位當
候選（全知），於是迷霧、掩體、草叢、視野扇形對 AI 全部不算數——玩家繞到背後、趴進草叢，
敵人照樣直線走過來。2026-08-22 依本節補回，對應關係：

| GDD（JS 版用語） | Godot 實作 |
|------------------|-----------|
| `canSee(observer, target)` | `Main._spots(p, u)`：視距（`class_base.sight`）× 視野扇形（±60° 全視距／側面 0.55／背後 0.3）× 天候光線 × 草叢隱蔽 × `_sight_clear` 視線 |
| `Fog.sideCanSee(side, target)` | `Main._side_sees(side, u)`：同陣營任一人看得到就算全隊知道（互相通報） |
| `AI.planUnit` 只考慮可見目標 | `Main._known_foes(e)` / `_nearest_known(e)`，`_ai_plan` 全面改用。**不是無條件全隊共享**：通報半徑 `relay` 讀 `data/difficulty.json`（ch1~2 120px ～ ch13~15 9999px） |
| 看不到 → 向我主堡推進 | 保留，但**先查槍聲記憶**（見下） |

**難度＝情報流通速度**（2026-08-22）：`difficulty.json` 每章的 `hearMemory`（記憶秒數）
與 `relay`（通報半徑）就是 AI 難度的第三、第四個旋鈕。低章節的部隊忘得快、通報不到，
高章節接近全隊即時共享。**高難度是知道得更多更久，不是血更厚**——部門文件第七節明訓
「高難度＝更聰明，不是更硬，禁止純數值膨脹」。

**聽覺是第二個情報來源**（GDD/15 F6）：`_hear_shot` 在開槍時，把「開槍當下的位置」記在
**聽得到的敵對單位身上**（`noise_px/py/t`，有效期 `HEAR_MEMORY_SEC = 20s`、聽距
`HEAR_PX = 460`）。AI 沒有可見目標但有未過期的槍聲記憶時，行為是「循槍聲查看」——
走向**開槍的那個位置**，不是對方現在的位置。聲音給的本來就是舊消息。

推論（設計上要成立的因果）：
- 開火會暴露自己 → 狙擊手打完該換位，這是遠程兵種的代價。
- 全隊安靜前進 → AI 真的不知道你在哪，會朝主堡推進，側翼包抄第一次有意義。
- 掩體與草叢對 AI 生效 → 這些東西不再只是「玩家的裝飾」。

**唯一仍保留的全知**：敵方行動順序排序（`_dist_to_nearest_foe`）用真實距離排先後。
那是回合順序的便利，不影響單位知道誰在哪；若日後要求嚴格，改成用已知目標排序即可。

## 6. 驗收判準（弱模型可機械檢查）

1. 開局：我方部署區周圍為 visible，其餘地圖為 unseen（全黑）。
   部署畫面中敵方單位數可存在於狀態，但可見敵軍數必須為 0。
2. 我方單位前進 → 前方 unseen 格轉 visible，敵單位在該格才現形。
3. 單位離開後該格轉 explored（暗、地形可見、敵人消失）。
4. `Fog.visible.size` 隨我方單位位置變化；全滅我方時 visible 為空。
