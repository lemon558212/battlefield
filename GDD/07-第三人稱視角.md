# 07. 第三人稱視角（行動模式 3D 化）設計
<!-- v0.1 設計稿 | 2026-07-07 | 這是「完整 3D 第三人稱」的實作藍圖，供後續 session 照此建置 -->

## 目標
**全程偽 3D 斜角戰場**（使用者 2026-07-08 拍板：一進戰鬥就是 3D）。兩種相機模式：
- **overview（斜角俯瞰）**：部署／指令／敵方回合——從玩家一側高空斜角俯瞰全場，玩家部隊在近景（畫面下方）、敵方在遠景（近地平線），露出天空與前景地面。
- **follow（第三人稱跟隨）**：玩家操控單一部隊時，相機滑到該單位後上方。
> 註：原 v0.1 設計為「指令/部署維持俯視、只有 act 才 3D」，已於 2026-07-08 依使用者要求改為全程 3D（本檔為現行規格）。

## 關鍵原則：只換「渲染與輸入方向」，不動遊戲邏輯
- 單位座標、HP、CP/AP、命中傷害、警戒射擊、迷霧——**全部維持現有 2D 俯視邏輯**（`combat.js`/`game.js` 不改規則）。
- 第三人稱只是**另一種畫面呈現 + 輸入方向轉換**。世界仍是 960×600 的平面；相機在這平面上方。
- 這是「渲染疊加層」，不是引擎重寫——降低風險的核心。

## 架構分件（建議新檔 `js/camera3d.js`）
1. **相機**：position (cx,cy,ch)、yaw（=選中單位 facing）、pitch（俯角，約 30–40°）、fov。
   相機置於選中單位**後方偏上**：cx = u.x - cos(f)*D、cy = u.y - sin(f)*D、ch = H（D≈70,H≈90 待調）。
2. **投影 `project(wx,wy,wz=0)`**：世界點→相機空間（平移 -cam、繞 z 轉 -yaw、繞 x 轉 -pitch）→透視除法→螢幕座標＋depth。
   ```
   dx=wx-cx, dy=wy-cy, dz=wz-ch
   // yaw 繞垂直軸、pitch 繞水平軸（標準 pinhole）
   rx = dx*cos(-yaw)-dy*sin(-yaw)
   ry = dx*sin(-yaw)+dy*cos(-yaw)
   ry2= ry*cos(pitch)-dz*sin(pitch)
   rz = ry*sin(pitch)+dz*cos(pitch)     // 前向深度
   if rz<=nearZ return null（在相機後方，剔除）
   sx = 480 + (rx/rz)*focal
   sy = 300 - (rz2.../rz)*focal          // 依實作調
   return {sx,sy,depth:rz,scale:focal/rz}
   ```
   （precise 公式建置時用單元測試校正：地平線、正前方一點、正右方一點。）
3. **地面**：把地形（草地紋理、水、障礙矩形四角）用 project 投影成梯形填色；或投影一張網格增強縱深。可預先把俯視地形貼圖當紋理，逐格投影。
4. **物件 = billboard**：每個單位/障礙投影其地面錨點取得 sx,sy,scale，畫一張**面向相機的立繪**（非俯視圖）。scale 隨深度縮放。畫序：depth 由遠到近（painter's algorithm）。
5. **天空**：地平線以上填漸層天色。

## 美術需求（重要風險）
- 現有 `sprites.js` 是**俯視圖**，第三人稱需要**側視/站姿立繪**。兩套並存：
  - 俯視 sprite（指令模式）保留。
  - 新增 billboard 立繪（行動模式）：可先用簡單的「站立人形＋武器」剪影，之後接 Kenney 側視素材。
- 這是為何 #2（Kenney 素材）與 #3 相關：行動模式的 billboard 可直接用側視素材。

## 輸入轉換
- 行動模式移動改為**相對相機**：拖曳上=forward（沿 facing）、左右=strafe/轉向。
  現有 `_pointerMove` 設 moveTarget 的邏輯改為：依相機 yaw 把螢幕方向轉成世界方向。
- 瞄準：畫面中央十字準心，點敵人立繪→沿用現有 `Combat` 命中判定。

## 分階段建置（每階段可獨立驗證、可 commit）
1. **P1 相機與投影** ✅：`camera3d.js` + project()/unproject()，單元測試校正（含反投影往復）。
2. **P2 地形與 billboard 渲染** ✅：`render3d.js`—地面透視格線＋建築3D盒＋單位 billboard＋深度排序＋天空。
3. **P3 輸入轉換** ✅：**行動模式相對相機操控**（拖曳垂直=前進/後退、水平=轉向；`moveUnit(setFacing=false)` 不由移動覆寫面向 → 相機 yaw 平滑不左右亂甩）；輕點敵人立繪→反投影→`Combat` 命中。overview 用固定相機，反投影點擊穩定（部署放置/指令選兵）。
4. **P4 轉場**：進/出 act 時相機在 overview↔follow 間平滑內插（目前為瞬切）。
5. **P5 立繪美術**：billboard 目前為程式化站姿佔位（面向相機正面剪影），接 Kenney 側視素材或自繪。

## 驗證判準
- P1：`project(相機正前方 D 遠的點)` 落在畫面中央附近；正右方點落右側；相機後方點回傳 null。
- P2：行動模式看得到地面向遠處收斂（透視）、單位近大遠小、遮擋順序正確。
- P3：拖曳上讓單位朝其面向前進；點敵人能開火且傷害與俯視一致。
- 效能：手機 act 模式 ≥30fps（地形投影需預算，必要時降解析度/簡化）。

## 不變量（絕不可破壞）
- 遊戲規則（combat/fog/ai/連線同步）零改動——3D 純表現層＋輸入方向轉換。單位座標仍是 960×600 平面。
- 全程 3D 只換「渲染 + 螢幕↔世界座標轉換（unproject）」；狀態機、CP/AP、命中、迷霧一律沿用。
- 零依賴、手機可玩、GitHub Pages 可跑。
