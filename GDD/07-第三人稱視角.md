# 07. 第三人稱視角（行動模式 3D 化）設計
<!-- v0.1 設計稿 | 2026-07-07 | 這是「完整 3D 第三人稱」的實作藍圖，供後續 session 照此建置 -->

## 目標
**全程偽 3D 斜角戰場**（使用者 2026-07-08 拍板：一進戰鬥就是 3D）。兩種相機模式：
- **overview（斜角俯瞰）**：部署／指令／敵方回合——從玩家一側高空斜角俯瞰全場，玩家部隊在近景（畫面下方）、敵方在遠景（近地平線），露出天空與前景地面。
- **follow（第三人稱跟隨）**：玩家操控單一部隊時，相機滑到該單位後上方。
> 註：原 v0.1 設計為「指令/部署維持俯視、只有 act 才 3D」，已於 2026-07-08 依使用者要求改為全程 3D（本檔為現行規格）。

## 關鍵原則：只換「渲染與輸入方向」，不動遊戲邏輯
- 單位座標、HP、CP/AP、命中傷害、警戒射擊、迷霧——**全部維持現有 2D 俯視邏輯**（`combat.js`/`game.js` 不改規則）。
- 第三人稱只是**另一種畫面呈現 + 輸入方向轉換**。世界仍是 960×600 的平面；相機在這平面上方。
- 這是「渲染疊加層」，不是引擎重寫——降低風險的核心。

## 架構分件（建議新檔 `js/camera3d.js`）
1. **相機**：position (cx,cy,ch)、yaw（=選中單位 facing）、pitch（俯角，約 30–40°）、fov。
   相機置於選中單位**後方偏上**：cx = u.x - cos(f)*D、cy = u.y - sin(f)*D、ch = H（D≈70,H≈90 待調）。
2. **投影 `project(wx,wy,wz=0)`**：世界點→相機空間（平移 -cam、繞 z 轉 -yaw、繞 x 轉 -pitch）→透視除法→螢幕座標＋depth。
   ```
   dx=wx-cx, dy=wy-cy, dz=wz-ch
   // yaw 繞垂直軸、pitch 繞水平軸（標準 pinhole）
   rx = dx*cos(-yaw)-dy*sin(-yaw)
   ry = dx*sin(-yaw)+dy*cos(-yaw)
   ry2= ry*cos(pitch)-dz*sin(pitch)
   rz = ry*sin(pitch)+dz*cos(pitch)     // 前向深度
   if rz<=nearZ return null（在相機後方，剔除）
   sx = 480 + (rx/rz)*focal
   sy = 300 - (rz2.../rz)*focal          // 依實作調
   return {sx,sy,depth:rz,scale:focal/rz}
   ```
   （precise 公式建置時用單元測試校正：地平線、正前方一點、正右方一點。）
3. **地面**：把地形（草地紋理、水、障礙矩形四角）用 project 投影成梯形填色；或投影一張網格增強縱深。可預先把俯視地形貼圖當紋理，逐格投影。
4. **物件 = billboard**：每個單位/障礙投影其地面錨點取得 sx,sy,scale，畫一張**面向相機的立繪**（非俯視圖）。scale 隨深度縮放。畫序：depth 由遠到近（painter's algorithm）。
5. **天空**：地平線以上填漸層天色。

## 美術需求（重要風險）
- 現有 `sprites.js` 是**俯視圖**，第三人稱需要**側視/站姿立繪**。兩套並存：
  - 俯視 sprite（指令模式）保留。
  - 新增 billboard 立繪（行動模式）：可先用簡單的「站立人形＋武器」剪影，之後接 Kenney 側視素材。
- 這是為何 #2（Kenney 素材）與 #3 相關：行動模式的 billboard 可直接用側視素材。

## 輸入轉換
- 行動模式移動改為**相對相機**：拖曳上=forward（沿 facing）、左右=strafe/轉向。
  現有 `_pointerMove` 設 moveTarget 的邏輯改為：依相機 yaw 把螢幕方向轉成世界方向。
- 瞄準：畫面中央十字準心，點敵人立繪→沿用現有 `Combat` 命中判定。
- **可見外觀優先命中**：選兵、瞄準與部署移除必須以目前畫面上真正顯示的 3D 模型或 2.5D 寫實 Sprite 包圍盒判定，不得只把點擊反投影到 `wz=0` 再用地面圓找單位。這是空軍（規則高度 52）與大型艦艇可直接點中本體的必要條件。
- 螢幕命中只納入我方或迷霧規則允許顯示的敵軍；拖曳超過門檻後不得觸發選取／瞄準。滑鼠最小目標 36 CSS px，觸控最小目標 48 CSS px。
- 滑鼠 6 CSS px／觸控 12 CSS px 的拖曳 dead-zone 內，`fwd`、`turn`、座標、面向與 AP 必須完全不變；跨過門檻後才開始移動，避免點擊手震偷走 AP。
- 沒有位移的按住仍視為點擊，不設 500／700ms 失效期限；慢按飛機本體、部署點或敵人立繪都必須生效。右鍵在行動模式不得啟動操控或瞄準。
- 多個可見單位命中框重疊時，精確命中優先，其次畫面前方深度，再比中心距；在近似同一螢幕點連點時於候選單位間輪替，不能永遠卡在陣列第一個。
- 視窗失焦或分頁隱藏時清空 WASD／方向鍵、拖曳與搖桿狀態；行動模式方向鍵不得同時捲動網頁。
- 空地部署與地圖座標仍走 `unproject()`；輸入事件只讀取「最後一幀實際顯示的相機」，不得為了反投影呼叫 instant snap 改變相機。

## 分階段建置（每階段可獨立驗證、可 commit）
1. **P1 相機與投影** ✅：`camera3d.js` + project()/unproject()，單元測試校正（含反投影往復）。
2. **P2 地形與 billboard 渲染** ✅：`render3d.js`—地面透視格線＋建築3D盒＋單位 billboard＋深度排序＋天空。
3. **P3 輸入轉換** ✅：**行動模式相對相機操控**（拖曳垂直=前進/後退、水平=轉向；`moveUnit(setFacing=false)` 不由移動覆寫面向 → 相機 yaw 平滑不左右亂甩）；輕點敵人立繪→反投影→`Combat` 命中。overview 用固定相機，反投影點擊穩定（部署放置/指令選兵）。
4. **P4 轉場** ✅：進/出 act 時相機在 overview↔follow 間依實際 `dt` 做指數平滑（60fps 時保留原約 0.16 手感）；點擊沿用最後渲染姿態，禁止在輸入事件中 instant 跳到目標相機。
5. **P5 立繪美術** ✅：程式化立繪依「單位面向 vs 相機看向」畫 **前/後/側** 三向（自機相機在後 → 顯示背面；正對之敵 → 正面）；士兵加背包/背帶/頭盔明暗，坦克依向畫頭燈/排氣/砲管朝向。（後續可再接更精緻素材。）

## 驗證判準
- P1：`project(相機正前方 D 遠的點)` 落在畫面中央附近；正右方點落右側；相機後方點回傳 null。
- P2：行動模式看得到地面向遠處收斂（透視）、單位近大遠小、遮擋順序正確。
- P3：拖曳上讓單位朝其面向前進；點敵人能開火且傷害與俯視一致。
- P3 點擊：指令模式直接點戰鬥機本體可進入行動；行動模式直接點敵機本體可開啟瞄準；在飛機附近但模型命中區外不得誤選。桌機與手機橫向都必須通過。
- P3 容錯：滑鼠抖動 5px／觸控抖動 11px 後放開仍是點擊且 AP 不變；滑鼠靜止按住 650ms／觸控 900ms 仍可選取；三個完全重疊的單位連點可輪替三個 id。
- 效能：手機 act 模式 ≥30fps（地形投影需預算，必要時降解析度/簡化）。

## 不變量（絕不可破壞）
- 遊戲規則（combat/fog/ai/連線同步）零改動——3D 純表現層＋輸入方向轉換。單位座標仍是 960×600 平面。
- 全程 3D 只換「渲染 + 螢幕↔世界座標轉換（unproject）」；狀態機、CP/AP、命中、迷霧一律沿用。
- 零依賴、手機可玩、GitHub Pages 可跑。

## 姿勢與鏡頭（2026-07-26 增訂，Godot 版）

### 移動姿勢對應（dept-04／dept-12）
| 姿勢 | 速度 | 動畫來源 | 說明 |
|------|------|----------|------|
| 站 | 3.0 m/s | 動作庫 run/walk | |
| 蹲行 | 1.35 m/s | 動作庫 crouch_walk | 掩體內 4m 範圍 |
| **匍匐** | **0.8 m/s** | **程式化（動畫層播 idle 不插手）** | 趴姿移動 |

**匍匐的動作規則**（使用者 2026-07-26 兩次指正後定案）：
1. **不可以播跑步動畫**。趴姿骨骼把軀幹壓平、動畫層卻在跑，腿在跑、手臂在擺＝自由式游泳。
2. **膝蓋先彎，再帶著大腿往外頂**（屈膝相位超前外展 0.5 rad）。小腿要折回身體中線
   （腳跟朝臀部），不可以跟著大腿往外——那是剪刀腿不是匍匐。
3. **沒在蹬地的那條腿要併攏**。基礎方向若是純朝後，兩腿會被髖寬撐開成 V 字，看起來像劈腿。
4. 左右腿相位差半圈＝交替蹬地；身體隨蹬地的那一腿側滾 9°（匍匐的使力感來自這裡）。
5. 靜止臥射時擺動強度為 0，起停漸進。

### 鏡頭
- **眼高跟著姿勢走**（站 1.52／蹲 1.05／趴 0.95m）。趴著時鏡頭若仍吊在站姿高度，
  人會被草叢淹沒、玩家看不到自己。趴姿刻意不取真實眼高，那太貼地會整個畫面都是草。
- **貼牆自動換肩**：左右肩各試算一次，哪側沒被擋就換過去（右肩優先，差 0.18 以上才換）。
- **鏡頭碰撞只擋半徑 0.35m 以上的圓與建築牆**：電線桿、柵欄那麼細的東西一直把鏡頭
  往回拉很煩，也遮不住什麼。
- 射線與圓求交**必須取進入交點**，不是「線段上離圓心最近的點」——寫成最近點時，
  鏡頭落在樹幹內部會算出 t≈1（最近點就是端點本身）＝判定成沒擋到，鏡頭停在樹幹裡。

### 驗收
- `[crawlchk]`：趴著走 2 秒量位移（要在匍匐速度區間）、動畫狀態（不可 run/walk）、髖高、
  **膝蓋外張量與屈膝角各取三個時間點**（只拍一張靜態圖看不出有沒有在交替）。
- `[camchk]`：貼牆時自動換肩、鏡頭離頭 1.5m 以上。

## 鍵盤操作（2026-07-26 使用者要求：不要什麼都靠滑鼠）

| 鍵 | 動作 |
|----|------|
| 方向鍵 / WASD | 移動（相對鏡頭方向） |
| Q / E | 左右轉視角（不用滑鼠也能玩） |
| C | 蹲下 ⇄ 自動 |
| Z | 伏臥 ⇄ 自動 |
| Space | 站起 |
| 滑鼠移動 | 轉視角（仍可用） |
| 滑鼠左鍵 | 對準心開火 |
| Esc | 離開行動模式 |

**玩家按鍵優先於自動判定**：原本蹲/趴是系統依「有沒有掩體、是不是狙擊手」自動決定；
玩家一旦按鍵指定姿勢，就以按鍵為準（`Unit.stance_cmd`）。特別是按了 Z 趴下之後，
不受「連續移動 2.5 秒自動起身」限制——那條規則是給自動臥射用的，
玩家明確要趴就不該被系統拉起來。

驗收 `[keychk]`：方向鍵能移動、Q 能轉視角、C/Z/Space 三個姿勢鍵都確實改變姿勢值。
