# 01. 戰鬥系統（BLiTZ 2D 轉譯）
<!-- v1.0 | 2026-07-07 | 所有公式以本檔為準；引擎實作在 js/game/combat.js -->

## 1. 回合結構：CP（Command Points）

- 我方階段開始時 CP = 基礎 6 + 存活坦克數 ×1（上限 10）。
- 在指令模式點選一個我方單位花 **1 CP**（坦克花 2 CP）進入行動模式。
- 同一單位一回合可被重複下令；第 N 次下令時該次 AP 上限 = 滿 AP × (0.7)^(N-1)。
- CP 用完或玩家按「結束回合」→ 敵方階段。

## 2. 行動模式：AP（Action Points）

- 進入行動模式後單位可自由移動（八方向/滑鼠目標點），每移動 1 px 消耗 `1/PXPERAP` AP（PXPERAP=3，即 1 AP = 3px）。
- 剩餘 AP 不足一個渲染幀的完整步長時，必須按剩餘 AP 比例走完最後一小段並歸零；禁止因幀率不同提前卡住或殘留「有 AP 卻走不了」的尾數。
- 單位斜向貼到海岸／深水作戰域邊界時，若 X 或 Y 單軸仍合法，應沿合法軸滑行；只有兩軸都非法時才完全停止。
- AP 歸零 → 只能原地開火或結束行動。
- 每次行動中**只能開火/丟雷/治療一次**（工兵修理、醫療包同計）。開火後仍可用剩餘 AP 移動（撤回掩體），忠實還原原作。
- 行動結束時單位面向最後移動方向，進入警戒狀態。

## 3. 警戒射擊（Interception Fire）——本作靈魂，不可閹割

- 具備警戒能力的兵種：步兵、突擊兵、機槍兵、坦克（車載機槍）。狙擊/迫砲/火箭/工兵**無**警戒射擊。
- 敵單位在行動模式中移動時，每 0.5 秒檢查一次：若進入我警戒單位的（射程 × 0.8）且視線無阻擋 → 自動對其射擊一次（傷害 × 0.5，不瞄部位）。
- 機槍兵警戒射擊間隔縮短為 0.25 秒——這就是機槍兵存在的意義。
- 蹲在草叢（隱蔽地形）的單位不觸發敵方警戒，直到自己開火。

## 4. 命中與傷害公式

```
命中率 = 武器基礎命中
        × 距離係數（distance/射程 ≤0.5 → 1.0；之後線性降至射程處 0.55；超射程不可射）
        × 部位係數（軀幹 1.0 / 頭部 0.55 / 坦克車體 1.0 / 坦克散熱器(尾部) 0.75）
        × 掩體係數（目標在掩體後且射線穿過掩體 → 0.5）
每發傷害 = 武器攻擊 × 部位倍率（頭 2.0 / 軀幹 1.0 / 散熱器 3.0）
          × 裝甲減免（max(0.1, 1 - 目標防禦/武器攻擊 × 0.5)）
一次開火 = 武器連發數 shots 發，逐發判定命中。
```

- 反裝甲武器（rocket 類）對步兵傷害 × 0.6（濺射半徑 24px 內減半）；
  一般槍械對坦克傷害固定 1（刮漆）——**剋制關係靠這兩條實現，不另設倍率表**。
- 迫砲/榴彈為拋物線武器：無視視線阻擋，但命中率 × 0.7，落點散布半徑 = 距離 × 0.08。

### 4b. 地形戰鬥修正（2026-07-28，鐵律 0：全部由物理推導；數值只放 `data/terrain_combat.json`）

命中率／殺傷力／閃避各乘上地形係數。與方向性掩體（cover_at）**分開、互不重複**：
壕溝與高草的防護已由掩體係數處理，這裡不再計。

**射手穩定度（乘在命中率上）**
| 條件 | 係數 | 物理理由 |
|------|------|----------|
| 涉水 ≥0.35m（及膝） | ×0.92 | 水裡沒有穩定射姿 |
| 涉水 ≥0.75m（及腰） | ×0.80 | 身體被水流帶動、無依託 |
| 陡坡 slope>0.35 | ×0.88 | 腳掌不平，據槍不穩 |
| 高於目標 ≥2.5m | ×1.10 | 俯視時目標暴露面大、視野開闊 |
| 低於目標 ≥2.5m | ×0.90 | 仰射只見頭肩輪廓 |

**目標閃避（乘在被命中率上，全向）**
| 條件 | 係數 | 物理理由 |
|------|------|----------|
| 目標涉水 ≥0.35m | ×1.12 | 水拖住腿，無法快速位移閃避 |
| 目標在彈坑內 | ×0.85 | 輪廓低於地平線（彈坑不在 _covers，此為唯一來源） |

**殺傷力**
| 條件 | 係數 | 物理理由 |
|------|------|----------|
| 濺射對壕溝內目標 | ×0.5 | 遮蔽陣地（defilade）：破片走直線 |
| 濺射對彈坑內目標 | ×0.65 | 同上，彈坑較淺 |
| 目標半身泡水（≥0.75m）直射 | ×0.85 | 打到下半身的部分被水吸收 |
| 高低差 | 不修正 | 幾公尺高度差不改變子彈動能——物理不成立就不加 |

### 4c. 命中與傷害的唯一真相＝`Main._shot_forecast`（2026-08-22）

先前「真的開火」（`_fire`）與「給玩家看的預測面板」（`_fire_preview`）**各算各的**。
於是同一輪加進 `_fire` 的高低差遮蔽與材質穿透，面板完全不知道——
面板寫 62%，實際結算是 45%。**會說謊的預測面板比沒有面板更糟**，
因為玩家是照著它做決策的。

現在兩邊都呼叫 `_shot_forecast(shooter, target, part)`，它回傳：

| 欄位 | 內容 |
|------|------|
| `hit` | 最終命中率（含距離、部位、姿勢、移動、傷勢、體力、天候、地形、掩體×高低差、材質穿透） |
| `dmg` | 最終傷害（含穿透後的威力衰減） |
| `blocked` | 這個部位的彈道是不是被實體擋死 |
| `why` | 給玩家看的修正明細（掩體 -X%、穿過 N 層／材質、移動中射擊、臥射、體力、天候、光線） |

`why` 會直接印在射擊面板上（GDD/13 資訊揭露）。
**加新修正時一律加在 `_shot_forecast` 裡**——加在 `_fire` 就等於再造一次面板說謊的病。

## 5. 地形與掩體

| 地形 | 效果 |
|------|------|
| 沙包/矮牆 | 相鄰蹲下：被命中率 ×0.5，且擋子彈視線 |
| 草叢 | 隱蔽（見第 3 節）；敵相距 <60px 仍會被發現 |
| 水域/彈坑 | 移動 AP 消耗 ×2 |
| 建築/岩石 | 完全阻擋移動與視線 |
| 主堡（旗點） | 步兵單位相鄰且該格無敵人 → 花一次「開火機會」佔領 |

### 5a. Terrain Action：蹲伏／隱蔽（2026-07-12）

- `scout/foot/heavy/engineer/special` 等地面人員靠近沙包，或位於草叢、壕溝、散兵坑、彈坑、碉堡內時，顯示「蹲伏掩蔽（C）」；坦克、艦艇與空軍不可使用。
- 玩家按 `C` 或 HUD 按鈕進入 Terrain Action；再次按下則站起。移動任何距離會自動站起，避免蹲伏狀態跟著單位穿越戰場。
- 只有已蹲伏的單位取得沙包／壕溝／散兵坑／彈坑／碉堡命中倍率；單純站在區域內不自動獲得完整掩體。
- 草叢只有「蹲伏且尚未開火」時提供隱蔽；站立或開火後可被正常偵測。
- 蹲伏不消耗 AP、CP 或開火機會；是 Action Mode 內的地形互動。敵方 AI 在行動結束且位於可用地形時自動蹲伏。

## 6. 敵方 AI（狀態機，禁止改成不可預測的隨機大雜燴）

每個敵單位每回合依序評估，取第一個成立者：
1. **殘血撤退**（HP<30%）：向最近友方旗點方向移動，尋找掩體。
2. **職責行為**：火箭兵找最近坦克攻擊；狙擊手找血最少步兵；機槍兵佔掩體警戒；步/突擊兵向最近敵人推進至射程 0.6 倍處開火；坦克推進轟最高價值目標。
3. **無目標**：向我方主堡推進。
AI 每回合花 CP 順序：先坦克、後步兵，CP 與玩家同規則。

## 7. 任務型態、勝敗與戰場評價（2026-08-22 全面改寫）

> 改寫的原因：本節 v1 寫「佔領敵主堡或殲滅」，但 Godot 版的 `_check_end` **只有殲滅**；
> 部門文件列的八種任務型態一種都沒實作；更嚴重的是 `story.json` 早就替五個章節寫好了
> `special`（限時／禁用兵種／靜默／增援波次／隱密），簡報也印給玩家看，
> 而 `grep special scripts/` 的結果是**零**——程式從來沒有讀過那個欄位。
> 玩家照著簡報打，規則卻不存在。

### 7a. 任務型態（`data/missions.json` 定義預設，章節在 `story.json` 掛 `mission`）

| type | 中文 | 勝利條件 | 失敗條件 | 參數 |
|------|------|----------|----------|------|
| `annihilate` | 殲滅 | 敵軍全滅 | 我方全滅 | —（**不掛 mission 就是這個，行為與本系統加入前完全相同**） |
| `capture` | 占領 | 我方站上敵主堡並守滿 `hold` 回合 | 敵方占我方主堡同樣回合數 | `hold`（預設 2） |
| `defend` | 防守 | 撐過第 `turns` 回合 | 我方全滅 | `turns`（預設 8） |
| `breakthrough` | 突破 | `count` 人抵達目標區 | 我方全滅 | `count`（預設 2） |
| `extract` | 撤離 | 指定單位抵達撤離區 | 我方全滅 | `who` |
| `escort` | 護送 | 同上 | **目標陣亡即敗** | `who` |

- **殲滅永遠是有效的勝利手段**：任何型態下把敵人全部打光都算完成。
- 目標區 `zone:{x,y,r}` 可在章節覆寫；不寫時 `capture`／`breakthrough` 用敵方主堡、
  `extract`／`escort` 用我方主堡。
- 任何型態都可加 `limit`（回合上限），超過即敗。
- 全域仍保留「30 回合未分勝負＝防守方勝」，但**任務判定優先**
  （防守任務撐到第 8 回合就該贏，不該被 30 回合平手蓋掉）。
- 未做：`rescue`（救援）。理由：需要「待救單位」這個新的單位狀態（不可控、可被解救、
  解救後轉為我方），是單位系統的改動而不是勝負判定的改動，等有劇情章節真的要用再做。

### 7b. 章節特殊規則（`story.json` 的 `special`，2026-08-22 實作）

| type | 章節 | 效果 |
|------|------|------|
| `timelimit` | ch05 | 超過 `turns` 回合＝敗（目標逃脫） |
| `ban` | ch07 | `cls` 兵種**不出現在部署名冊上** |
| `silence` | ch10 | 第 `turns` 回合前開火 → 敵軍增援 3 人（只觸發一次） |
| `waves` | ch12、ch15 | 在 `turns` 列出的回合各增援 3 人 |
| `stealth` | ch14 | 擊殺超過 `limit` → 增援 4 人 |

任務目標與特殊規則都印在 HUD 的目標列（`UI.show_objective`）——
**任務不寫在畫面上等於沒有任務**。

### 7c. 戰場評價 S~C（門檻放 `data/missions.json` 的 `rating`）

先前是 `var rank := "A" if w else ""`——不管打幾回合、死幾個人都是 A，評價欄是裝飾。

    分數 = 100 － 超過標準回合數 ×4 ＋ 提前回合數 ×3 － 我方陣亡數 ×12
    S ≥ 100 ／ A ≥ 85 ／ B ≥ 70 ／ C 其餘

實測：3 回合零傷亡＝S、26 回合＝C。

## 8. 部署規則

每張地圖定義部署點數上限（教學關 1000）。每單位有 cost（見 02 檔）。坦克每隊最多 2 輛。部署格限我方區域。

## 戰場評價（2026-07-19 新增，dept-03）

勝利時依「回合數＋我方陣亡數」給予評價，敗北不評價：

| 階級 | 條件 |
|------|------|
| S | 回合 ≤ 6 且我方零陣亡 |
| A | 回合 ≤ 8 或我方零陣亡 |
| B | 回合 ≤ 12 |
| C | 其他 |

- 回合數＝結束當下 Game.turn；陣亡數＝我方 alive=false 單位數。
- 防守方撐滿 30 回合獲勝屬時限勝：回合條件不適用，改以陣亡數評價（0 陣亡=S、≤2=A、≤4=B、其他 C）。
- UI 呈現：結算畫面大字拍章動畫（S 金、A 藍、B 銅、C 灰），鳴潮式斜切風格。
