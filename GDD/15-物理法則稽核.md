# GDD/15 — 物理法則稽核表（鐵律 0 的全域對照）

> 使用者 2026-07-27 原話：「我說的物理法則不是遊戲哩，是真實世界的，
> 而且是套用在遊戲裡任何有關物理的一切，所以根本不只這些。」
>
> 鐵律 0 不是一張「碰撞待辦清單」，是**全遊戲的預設前提**：
> 任何東西先假設「現實怎樣就怎樣」，做不到或刻意不做的，必須在本表寫明理由並標記為**例外**。
> 沒寫在本表裡的「不真實」一律視為缺陷，不是設計。

狀態記號：`✅ 符合` / `⚠ 已知例外（本表有理由）` / `❌ 缺陷（違反鐵律 0 且沒有理由）`

### ★ A2/A3 是**經使用者核定的設計例外**（2026-07-27）

現實中步槍有效射程 300~500m、狙擊 800m+、開闊地肉眼可辨識站立人形 300m 以上。
本遊戲刻意壓縮到 10~21m 級。**使用者原話：「維持現況，這才是遊戲動智慧的賣點之一」。**

理由（＝為什麼這條不算違反鐵律 0）：**壓縮交戰距離是戰術深度的來源**。
射程一旦寫實，任何人站在開闊地都會被 500m 外打死，掩體、推進、迂迴、警戒射擊
全部失去意義，遊戲會退化成「先看到的人贏」。VC 式棋盤距離讓「多走三步繞到側翼」
成為有意義的決策——這正是本作要賣的東西。

**因此：**
- 本表不再把 A2/A3 視為缺陷。
- **但尺度必須內部一致**：任何新加的距離參數（新武器射程、偵測半徑、AI 推進距離、
  技能範圍）一律沿用這套壓縮尺度，不可以混入真實公尺數。
- 唯一仍應修正的是**表現層的違和**：例如遠山、森林帶的視覺尺度暗示了公里級戰場，
  而交戰在 10m 內發生。這屬於美術與鏡頭問題，不是物理問題。

| C7 | 屍體可跨過 | ⚠ 例外：真實上跨得過去，只是不該完全無阻；可接受 | ⚠ |
| C8 | 路面與瓦礫不擋 | ⚠ 例外：真實上跨得過去 | ⚠ |
| C9 | **窗戶** | 窗洞在牆上扣掉了，於是**人可以直接走過窗洞**，沒有翻窗這件事 | ❌ |
| C10 | **樓層與牆的關係** | 二樓有樓板了，但**沒有二樓的窗台高度判定**，站二樓射擊仍照平地算遮蔽 | ❌ |
| C11 | **工事的碰撞只有一條中線** | 沙包工事只有「主牆中線 ±0.30m」進 `_blockers`；**散落的袋子（離主牆最遠 1.1m）完全沒有碰撞**，走過去腿直接插進袋子（使用者 2026-07-27 截圖）。**本次補上**（散落袋登記成矮障礙） | ✅ 已修 |
| C12 | **矮物件不能踩上去** | 全場障礙一律「水平推開」，沒有任何東西有**頂面支撐**。**本次補上通則**：`STEP_UP = 0.5m`，高度 ≤ 0.5m 的障礙改給頂面支撐（踩上去），高於 0.5m 的照舊水平擋 | ✅ 已修 |

| C13 | **深水圍欄從來沒生效過** | `_build_water()` 把圍欄 append 進 `_blockers`，但它跑在 `_blockers = []`（重建場景的清空）**之前**，整批被清掉。畫面上是 2.3m 深的海，走過去像草地 | ✅ 已修 |

**C11/C12 是同一個結構問題的兩面**，也是 C1「已經做好了」之所以看起來還是穿模的原因：
碰撞是一套 2D 俯視的「圓／線段推擠」，只有**水平**維度。
所以任何「畫得比碰撞線寬」的東西（梯形沙包堆的底、散落物、泥土過渡層）都會被穿過去，
而任何「矮到應該踩上去」的東西也只會把人往旁邊推。
→ 通則應為：**畫得出來的東西一定要有碰撞；高度 ≤ 0.5m 的給頂面支撐（踩上去），
高於 0.5m 的水平擋。** 這條做完，C1 才是真的成立。

## 修復優先序建議

按「玩家最容易看出來 × 改動成本」排：

**第一梯（現在就該做，成本低、感受強）**
1. **F1~F4 音效空間化**：目前一槍打出去是靜音的。用 `AudioStreamPlayer3D` 就有距離衰減，
   這是投入產出比最高的一項。
2. **B4 加速度與慣性**：人瞬間起步瞬間煞停，是「像遊戲不像人」最主要的來源之一，
   落點只有 `Unit.move_dir` 與 `_process` 的位移那幾行。
3. **H3 把 `terrain_mobility.json` 接起來**：資料已經寫好了，程式沒讀。

**第二梯（要動規則，需要使用者拍板）**
4. **A2/A3 射程與視野的尺度**（見上方三種走法）。
5. **D6 爆炸範圍傷害**：迫砲與火箭沒有範圍就沒有存在意義。
6. **I1 視野角度**：加上視野扇形，同時決定背後多遠算「察覺」。

**第三梯（工程量大）**
7. D4 拋射彈道、D5 材質貫穿、G1 可破壞環境、H5 天候、I2 負重疲勞。

## 維護規則

- **新功能一律先過本表**：做任何東西前，對照 A~I 九類問一次「現實裡這件事怎麼運作」。
- **不做的要寫進本表並標 ⚠**，附理由（效能、玩法、工程量都算理由，「忘了」不算）。
- 本表與 `CLAUDE.md` 鐵律 0 的五條推論是同一件事的兩個粒度：
  鐵律 0 是原則，本表是逐項的帳。
