## 0. 現行美術方向（2026-07-10 拍板）

- **動作影片透明規格**：遊戲內正式播放路徑為「生成影片拆成透明連續影格圖集」，由 Three.js 逐格播放；不得依賴瀏覽器 VideoTexture、硬體影片解碼或執行時綠幕 shader。影格圖集尚未載入或失敗時，必須保持原始 PNG 可見，不可切成黑色平面。
- **戰場主畫面**：高品質風格化 3D。以清楚、略誇張的裝備輪廓為優先，搭配低至中等面數、PBR 感材質與可在手機維持效能的貼圖。
- **角色卡／圖鑑／宣傳圖**：水彩軍事插畫感，保留手繪邊線與紙張質地；不拿 2D 插畫假裝成 3D 模型。
- **材質細節**：吸收半寫實方向的刮痕、塵土、金屬粗糙度，但不追求照片級模型密度。
- 美術方向比較原圖保存在 `assets/art-direction/style-comparison-v1.png`；後續資產不得偏離其中央欄的主方向。

### 3D 與生圖的責任分界

1. AI 生圖負責兵種造型設計、三視圖參考、角色卡與圖鑑立繪。
2. 戰場環境、相機、座標、飛行高度與特效維持真 3D；依 2026-07-11 使用者更正，單位的主要可見外觀可使用既有寫實生圖的 2.5D 去背切片，但必須誠實標示其不是可繞背觀看的完整 GLB。
3. 生圖不能直接視為可用 3D 模型；模型仍需建模、骨架、動畫、材質與遊戲尺寸校正。
4. 所有生成資產都需保留提示詞、版本與用途說明；不得覆蓋既有圖，改用版本化檔名。

## 1. 雙軌制（User 指定「程式化＋圖片並行」的落地）

```
繪製單位時：
  若 assets/units/{nationId}_{cls}.png 已載入成功 → 畫該圖（尊重真實軍種美術）
  否則 → 呼叫程式化向量繪製函式 sprites.js drawX(cls)（零依賴 fallback）
```

- 引擎永遠具備向量 fallback：即使一張 png 都沒有，遊戲照樣好看、可玩。
- 圖片放置規則寫在 `assets/README.md`：檔名 `{nationId}_{cls}.png`（如 `usa_tank.png`），
  48×48 透明背景、俯視、頭朝右（引擎依 facing 旋轉）。User 可隨時放圖，無需改碼。
- **能力誠實**：AI 生圖可交付概念圖與點陣美術；真 3D 模型仍須由既有 CC0/CC-BY GLB、程式化裝備或後續人工建模落地。不得把概念圖完成視為 3D 資產完成。

## 2. 程式化向量繪製規範（sprites.js）

每兵種一個 `draw{Cls}(ctx, u, colors)` 函式，colors = {uniform, accent, skin, metal}。共通要素：

- **陸兵（land 人形）**：橢圓身體（迷彩色）＋圓頭盔（深色）＋武器輪廓（沿 facing 方向的短線/多邊形）＋兵種識別色臂章點。各兵種差異：
  - rifleman 標準步槍剪影；mg 較粗槍管＋兩腳架三角；sniper 長槍管＋鏡面反光點；
  - mortar 背迫砲板；at 肩扛筒狀；engineer 背工具包（方塊）；specops 深色貼身＋消音器；sam 背飛彈發射箱。
- **坦克/裝甲**：車體矩形＋砲塔＋沿 facing 砲管；履帶紋（兩側短線）；散熱器黃點（弱點提示）。
- **艦艇（sea）**：拉長船體梭形（灰）＋艦橋方塊＋依 facing 的主砲/飛彈；destroyer 大、missileboat 小快、lst 寬扁艙門、submarine 低矮潛沒感（半透明水線）。
- **飛機（air）**：後掠翼三角剪影＋機身；fighter 尖細、attacker 粗壯掛彈、gunship 直升機（旋翼圓圈＋機身）；air 單位畫陰影投影於地面表示飛行高度。

## 3. 配色（各國 uniformColor 已在 data-nations.js）

- 陸兵用該國 uniformColor（迷彩主色），accent 取國旗第 2 色。
- 敵我識別：我方描藍邊 `#7db4ff`、敵方描紅邊 `#ff9d8a`（維持 v1）。
- 迷彩紋理：身體橢圓上疊 2-3 個較深色斑塊（程式隨機但以 unit.id 為種子固定），避免純色呆板。

## 4. 品質判準（弱模型驗收用；非品味類）

1. 站在一起的 9 個不同陸兵，肉眼可區分兵種（造型差異，不只顏色）。
2. 不同國家同兵種，迷彩主色明顯不同。
3. 艦艇明顯比人形大（destroyer ≥ 40px 長），飛機有地面投影。
4. 選中單位有高亮環、血條/AP 條不被 sprite 蓋住。

## 5. 品味類的熔斷（誠實條款）

「整體氛圍夠不夠帥、配色順不順眼」屬品味決策：弱模型做到 §4 的客觀判準即算達標；
若 User 用「太陽春／不夠帥」等口語回饋，走 harness/02 品味流程做 2-3 變體給 User 選，不自行反覆微調。

### 寫實召喚同源外觀（2026-07-11 使用者更正）

- `assets/art-direction/land-roster-concept-v1.png` 與 `sea-air-roster-concept-v1.png` 是 17 兵種目前的**正式可見美術來源**，不是只供參考的卡片圖。
- 部署按鈕顯示 `assets/units-realistic/{兵種}.png`；召喚後以該圖作 image-to-video 第一幀與身份參考，播放同一外觀的逐幀動作影片，召喚前後必須是同一個造型。
- 真 3D GLB／程序化幾何仍保留作尺寸、規則錨點與圖片載入失敗時的 fallback；寫實圖成功後不得讓低面數外觀透出。
- 去背只移除由格位邊界連通的中性背景；武器、天線、旋翼、砲管與艦桅等細部不得因去背消失。驗證後成品保存於 `assets/units-realistic/{兵種}.png`，執行時直接載入；圖集即時去背只作缺檔後備。
- 專案必須支援直接雙擊 `index.html` 的 `file://` 模式。由於瀏覽器可能允許本機 PNG 顯示、卻拒絕把它上傳成 WebGL 材質，17 張正式 PNG 另機械式打包至 `js/data-unit-art.js` 的 data URI；執行時優先使用此同內容內嵌來源，不能要求玩家另開伺服器。
- 影片材質未通過可用性條件時，先回退同源 PNG，再回退 GLB／程序化幾何。可用性至少包含：影片可解碼、自動靜音播放成功、首幀為同一原圖外觀、背景可去除、動作不是整體抖動。任何影片或圖片失敗都必須至少留下可辨識模型，禁止只剩血條、選取環或透明空位。
- 影片平面需保留地面接觸陰影、空軍地面投影、艦艇航跡、選取環與現有螢幕點擊範圍；不得為了換影片退回 2D 地圖。
- 此階段不宣稱已完成可從任意角度觀看的寫實 3D 模型；後續若取得逐兵種合規 GLB，再用同一生圖作建模與材質基準。

## 7. 模型品質閘門（2026-07-17）

- 檔案存在、能載入或帶有骨架動畫，不代表可以進入正式戰場。
- 每個人物模型必須通過同尺寸正面與側面近照、網格缺面、手掌與武器接觸、待機、走路、射擊、受擊檢查。
- 出現表面破碎、透明缺面、肢體融合、武器懸空、比例異常或風格明顯不符者，必須標記為隔離資產，程式不得載入。
- 當某兵種尚無合格專用模型時，允許暫時使用已通過檢查的共用軍人基礎模型，但不得宣稱該兵種已完成專用模型。
- 禁止為了製造兵種差異，把未綁定骨架的方塊、圓柱裝備直接疊在人物根節點上。

- 戰場內的步兵、戰車、飛機、直升機、艦艇一律顯示 3D 網格；部署卡圖片不可在載入成功時反過來遮住 3D 模型。
- 九種人員兵種可共用合格人體與骨架技術，但每種須組成不同的最終可見模型；至少有三項幾何差異（武器、背負裝備、頭部／護甲、體格）才能視為不同兵種。
- fighter、attacker、gunship 必須分別呈現制空機、對地攻擊機、旋翼機結構；destroyer、missileboat、lst、submarine 必須是不同艦體而非等比縮放；tank 的砲塔、路輪與履帶須為可動節點。
- 機械動作不可由整體搖晃代替：直升機主／尾旋翼、坦克路輪／砲塔、艦艇航跡、飛機傾側與控制面均須由獨立節點更新。

## 角色外觀系統 v2（2026-07-31 使用者核定：敵我識別＋人設唯一性）

使用者原話：「每一個模型都要符合人設，但千萬不要敵我軍有長的一樣，然後自己方也不能一樣。」

### 1. 唯一性規則（程式可驗，lookshots 斷言）
- 外觀簽名 = (基底模型, 頭具, 背具, 主色 coat)。
- **敵我基底完全分池**：敵軍專用 hr_soldier / hr_swat（我方永不使用）→ 剪影天生不同。
- 我方 9 位具名角色**各佔一顆基底不重複**，並各配專屬頭具/背具/人設配色（char_look）。
- 敵軍同兵種同款＝制式軍隊的真實（識別靠兵種裝具差異＋整隊冷灰綠制服＋紅環）。

### 2. 裝具目錄（程序化低多邊形，BoneAttachment 掛骨）
頭具：helmet（圓盔+沿）/ helmet_net（盔+偽裝網塊）/ beret（貝雷歪戴）/ cap（帽簷帽）/
boonie（闊邊帽）/ hood（連帽）/ balaclava（頭套）/ goggles（帽+護目鏡）
背具：none / slim（小包）/ ruck（大背囊+蓋）/ radio（電台+天線）/ tube（背筒）/ ammo（彈箱）
