## 0. 怎麼在遠端容器裡做完整驗收（2026-08-22 實測可行）

先前的認知是「遠端 session 沒有 Godot，只能改碼、不能驗收」。實測不是這樣：

```bash
# 1) 下載與專案完全同版的引擎（版本要對，日誌開頭那一行就是版本）
curl -sSL -o godot.zip \
  https://github.com/godotengine/godot/releases/download/4.7.1-stable/Godot_v4.7.1-stable_linux.x86_64.zip
unzip -q godot.zip && chmod +x Godot_v4.7.1-stable_linux.x86_64

# 2) 首次匯入資產（442MB、約 20 分鐘，只需一次）
./Godot_v4.7.1-stable_linux.x86_64 --headless --path godot --import

# 3) 跑驗收台。★ 不可以用 --headless：
#    headless 的 DisplayServer 下合成滑鼠事件不會按到按鈕（實測卡在「FAIL 無章節按鈕」），
#    而且視窗變成 1280×1280。要用 xvfb ＋ opengl3。
xvfb-run -a -s "-screen 0 1280x720x24" ./Godot_v4.7.1-stable_linux.x86_64 \
  --path godot --rendering-driver opengl3 -- locochk
```

**已知代價**：軟體渲染（llvmpipe）只有 2~7 fps。數值型斷言照樣成立，但
**任何「單幀多少」的門檻都會假性 FAIL**——那不是程式壞了，是門檻寫錯了（見 §1 第一條）。
截圖也會比本機難看，所以**不要把這個環境跑出來的 qa/*.png 提交進版控**。

## 1. 本輪（2026-08-22）已完成

1. **locochk 的轉向斷言改成幀率無關**：原本驗「單幀最大轉 < 22°」，那是角速度 × 幀時，
   在慢機器上必 FAIL。改驗角速度（度/秒），上限對照 `LocomotionProfile.turn_rate_fast`。
2. **AI 全知關掉（GDD/05 §5 補回）**：`_ai_plan` 原本把所有活著的敵方單位當候選，
   迷霧、掩體、草叢、視野扇形對 AI 全都不算數。改用 `_known_foes` / `_nearest_known`，
   與玩家共用同一支 `_spots`。
3. **AI 聽覺成為情報（GDD/15 F6）**：`_hear_shot` 把「開槍當下的位置」記進聽者，
   20 秒有效；看不到人但記得聲音 → 「循槍聲查看」。
4. **新驗收台 `-- aichk`**：把上面三件事逐條量出來（見該台的輸出）。
5. **GDD/15 新增 J 類「情報與認知」**，把「誰能知道什麼」當成獨立一類物理來管。

## 2. 建議下一步（按投資報酬率排）

### 第一梯：現在就能做，且能量得出來
- **J5 屍體是情報**：AI 走過同伴屍體不會提高警覺。落點在 `_ai_plan` 的情報來源，
  與 §1-3 同一條路徑，成本低、戰術感受明顯。
- **J6 腳步與引擎聲**：目前只有槍聲會產生情報。跑步／坦克引擎該有更短的傳播距離
  （槍聲 460px、跑步 ~120px、坦克 ~260px），讓「蹲行接近」真的有價值。
- **警戒射擊要先「看得到」**：`_intercept_tick` 目前只驗彈道通不通（`_shot_clear_units`）＋
  射程＋不在草叢，**不看視野扇形**——背後有人跑過去照樣自動開火。這對雙方對稱，
  所以不是作弊，但違反鐵律 0②與 I1（人看不到背後）。改法是加一道 `_spots(u, m)`。
  ⚠ 這條會動到平衡與既有 `selftest` 的 alertchk，本輪**刻意沒做**：
  遠端容器 2 fps 跑不動 selftest 那台截圖馬拉松，改動沒辦法在同一輪驗完。
  要做請在本機跑 `-- selftest` 與兩章 `-- play` 對照勝負與迎擊次數。
- **AI 難度分級接上情報**：`data/difficulty.json` 已有 focus/cover/flank，
  可再加「記憶時間」與「通報範圍」——高難度＝情報流通快，不是數值膨脹（部門文件明訓）。

### 第二梯：需要使用者拍板
- **G1 可破壞環境**：工事與中景為了 draw call 合併成單一網格，逐件摧毀要先拆合併，
  是一次真正的重構。要不要做、做到什麼程度，需要先定範圍。
- **H2 涉水表現**：水裡照播走路動畫、沒有水花。屬於動畫與特效資產缺口。
- **跑步片段**：`run/sprint` 仍有滑步（`Jog_Fwd` 重定向到 hr_ 骨架後腿幾乎不掃），
  真正的解法是換一份可用的跑步動畫資產，不是再調參數。

### 第三梯：資產產線（需要 64GB 那台，見 GDD/17 §六）
- 八機種載具成品模型、九名角色的動畫烘焙。這條線與本容器無關，別在這裡空轉。
