# 開發總路由（部門體系權威：專案根目錄《戰場女武神類型遊戲開發部門與工作項目.docx》）

本專案由單一 AI agent 分飾十五部門。任何工作先在此定位「主辦部門」，再依交接流程執行。
各部門 skill：dept-01-production ~ dept-16-military-advisor（`/dept-` 開頭）。

## 部門間交接流程（文件第十四節，照此順序跑）

1. **劇情與戰役需求提出**（07）：章節背景、戰役目的、角色事件與情緒目標
2. **任務與地圖設計**（06）：目標、地圖、敵軍部署、事件與多種解法
3. **系統與數值確認**（03/05）：規則、兵種、武器、命令及評價條件
4. **概念與視覺設計**（11）：場景、角色、敵軍、載具、色彩與氣氛
5. **程式與工具實作**（08/09/10）：特殊規則、事件、AI、相機、介面及資料
6. **正式資產製作**（11/12/14）：角色、場景、動畫、特效、音訊
7. **整合與測試**（15）：功能、AI、平衡、關卡、效能
8. **驗收與版本提交**（01/02）：依品質標準驗收後 commit+push

## 最不可削弱的核心功能（文件第十五節，資源衝突時依此取捨）

1. 核心戰棋系統 2. 第三人稱操作與戰鬥 3. 戰術地圖與任務 4. 戰術AI與尋路
5. 數值與平衡 6. 角色與劇情 7. UI與資訊視覺化 8. QA與關卡測試

**總結原則**：不是做「回合制射擊」，而是讓戰術地圖、即時移動、角色能力、敵軍AI、
戰役節奏與劇情情感形成彼此支援的完整循環。

## 本專案憲法（凌駕一切部門決策）

- 免建置：vendored 單檔庫，index.html 直開即玩、手機可跑（CLAUDE.md 鐵律 2）
- 資料與邏輯分離（data/ 與 js/data-*.js）；GDD 是規格真相
- 美術方向＝水彩手繪風非寫實；開源優先不重造輪子（CC0/CC-BY 需署名記錄）
- 歷史鐵則見 GDD/10（殭屍骨骼/sRGB洗白/迷霧黑塊/喀噠聲/同模改名 五大事故）
