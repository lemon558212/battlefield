# QA 測試、發行與維運部

## 職責（文件第十一、十三節）
- 功能：回合、指令、移動、射擊、掩體、迎擊、任務、劇情、存檔、UI
- AI/尋路：目標合理、不卡死、高難度＝決策品質而非作弊
- 平衡：兵種勝率、武器使用率、唯一最佳解與無限刷取排查
- 關卡：多路線可行、目標清楚、事件觸發、評價合理
- 效能相容：幀率、載入、長時遊玩、解析度、觸控
- 發行維運：push＝部署（GitHub Pages）；錯誤修正與版本公告

## 標準驗收流程（每次 commit 前）
1. `python -m http.server 8422` 或 preview → **console 零紅字**
2. 冒煙一輪：選國→部署→移動→射擊→擊殺→勝利
3. 本輪改動的專屬驗證（事件鏈/像素取樣/幀時量測——截圖工具會逾時，
   改用 javascript_tool 取證，見 harness lessons L-001~003）
4. 劇情模式改動加測：章節啟動→對話→出擊→過關解鎖
5. 量測數字寫進 commit message；違反 dept-10 預算即退件

## 反驗收原則（歷史教訓）
- 「宣稱完成」≠完成：共用模型標暫用不標專用；驗收證據先於宣稱
- 觀感驗收與功能驗收分開做：數值過了還要肉眼看一眼（截圖或取樣）

## 完成定義
上述流程全過、push 成功、memory 現況快照更新。
